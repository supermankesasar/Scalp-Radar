# Database relocation (Windows, 26 Nov 2026)

User requested moving the growing database off default C drive. Developer chose D:\ScalpRadar\data\signals.sqlite3 (assumes D exists; no device access or capacity verified). Default stays unchanged for installations that have not migrated. Stop entire scanner and launcher first, then run MIGRATE-DATABASE.bat and type YES. The migration uses SQLite backup to include WAL data, checks integrity and refuses to overwrite an existing target. Original source retained. It writes a small location config to %LOCALAPPDATA%\ScalpRadar\database-location.json after the copy succeeds. Both launcher and exporter honor it; explicit SCANNER_DB has priority and must be cleared before migration. Configured missing database fails closed rather than silently creating a new one on C. Runtime logs are copied when possible; existing destination logs not overwritten. After migration, exports and their temporary snapshots use the selected drive (D:\ScalpRadar\exports). Confirm displayed path and export before manually removing old C backup. No automatic deletion or merging. Older releases without the location config reader must not be run after migration. Custom destination can be passed as a quoted absolute path argument to MIGRATE-DATABASE.bat. CI verifies migration behavior, not user's actual disk. If failure leaves an existing destination, inspect both copies before retrying; never blindly overwrite.


Startup updater keeps application checkout separate from configured DB. Example D:\ScalpRadar-App for source, D:\ScalpRadar\data for existing configured DB. Do not clone into or delete database directory. If using a legacy ZIP-local DB only, migrate first using existing launcher/migration flow. START-AUTO.bat does not alter database-location.json or SCANNER_DB; standard launcher continues selecting them.
