## P0.1 implementation — branch only, NOT release approval

p0_recovery.py adds manually initiated, offline SQLite recovery points, outside current checkout. Windows CLI requires explicit STOPPED confirmation, legacy auto-launch lock and port 8765 free; direct launcher does not share this lock, so operator must stop ALL launchers/writers and avoid concurrent start. Uses read-only source transaction and SQLite backup API (committed WAL included); unique staging directory, free-space check including WAL + 64 MiB reserve, recognized critical tables, schema SHA256, user_version and available critical table counts matched, quick_check and integrity_check, close/reopen, standalone DELETE-mode DB, SHA256 and bytes verified. Publishes unique directory only after verification; no automatic pruning or replacement, no production DB/location mutation. Manifest records source path, UTC, checkout SHA/dirty state when Git available, Python/websockets/requirements identity, knownGood=false; copies saved location config and runtime logs if present. Source identity is not health certification. Hash is corruption detection, not authentication against hostile edits. Directory rename is atomic visibility under normal filesystem operation; power-loss durability not certified. Full counts/integrity/hash on multi-GB DB can be expensive; actual throughput/space unmeasured.

Commands from this branch (do NOT switch a running auto-updated checkout):
- After all scanner/launcher processes stopped: `py -3 p0_recovery.py backup --parent "D:\ScalpRadar\recovery"` (example only if drive exists and capacity verified; otherwise choose actual external directory). Default is sibling recovery directory relative to selected database, may reject legacy checkout-local paths.
- `py -3 p0_recovery.py verify "<recovery-point-directory>"`.
- `py -3 p0_recovery.py restore-copy "<recovery-point-directory>" --parent "<separate-external-directory>"`. Creates a fresh signals.sqlite3; never selects it or overwrites current data. Preserve all newer data, document gap and verify compatible code/schema before any manual cutover.
